عرض متطلبات — تطبيقات وصلة (Wasla)

الغرض: إرسال متطلبات لمبرمج/شركة تطوير لتقدير التكلفة والمدة.
المنصة: Flutter (Android + iOS)
الخلفية الحالية: نظام ويب جاهز (Laravel + API) — التطبيقات تتصل بنفس الـ Backend قدر الإمكان.
التاريخ: 2026-08-20

ملخص المشروع

#التطبيقالجمهورالهدف
1 تطبيق الزبون العملاء تسوق من متجر وصلة + طلب من مواقع خارجية + دفع ومتابعة الطلبات
2 تطبيق التوصيل السائق / المندوب استلام الطلبات، تحديث الحالة، تتبع التوصيل
يُرجى تسعير كل تطبيق منفصل، مع خيار خصم عند تنفيذ الاثنين معاً.

التطبيق 1 — تطبيق الزبون (Flutter)

1) الهوية واللغة

  • واجهة عربية بالكامل (RTL)
  • هوية بصرية حسب براند وصلة (لون أساسي تقريباً #1c7282)
  • دعم Android و iOS
  • إشعارات Push (FCM)

2) الحساب والتسجيل

  • تسجيل حساب جديد
  • تسجيل دخول / تسجيل خروج
  • عرض الملف الشخصي
  • إدارة عناوين التوصيل (إضافة / تعديل / حذف)

3) المتجر المحلي (منتجات وصلة)

  • تصفح المنتجات مع بحث وفلاتر (فئة، ماركة، بحث نصي)
  • صفحة منتج: صور متعددة، اختيار لون، عرض كل المقاسات (غير المتوفر معطّل)، السعر بالليرة، إضافة للسلة
  • قائمة الأمنيات (Wishlist) — اختيارية في المرحلة الأولى إذا أثّرت على السعر

4) الشراء من الخارج (ميزة أساسية)

المنصات: SHEIN، Trendyol، Temu، Noon، Amazon (وغيرها حسب الإعدادات).

  • لصق رابط منتج → معاينة السعر بالليرة (منتج + شحن + رسوم خدمة) → إضافة للسلة / طلب شراء
  • تصفح داخل المنصة من داخل التطبيق (WebView أو كتالوج عبر API)

5) السلة والدفع

  • سلة مختلطة (محلي + خارجي إن أمكن)
  • إتمام الطلب (Checkout)
  • طرق الدفع: كاش عند الاستلام، سيرياتيل كاش، MTN كاش، شام كاش، تحويل بنكي، رصيد المتجر
  • رفع صورة إيصال عند الحاجة
  • صفحة تأكيد الطلب

6) طلباتي ومتابعة الحالة

  • طلبات المتجر المحلي + طلبات الشراء من الخارج
  • تفاصيل: منتجات، أسعار، حالة الطلب، حالة الدفع
  • إشعارات عند تغيّر الحالة / تأكيد الدفع

7) التكامل التقني

  • الاتصال بـ API الحالي (Laravel Sanctum)
  • سلة للضيف ثم تسجيل دخول عند الدفع
  • رفع صور الإيصالات
  • الأسعار والرسوم من الـ Backend (بدون إعادة حساب محلي خاطئ)

8) خارج النطاق (ما لم يُطلب)

  • لوحة أدمن داخل التطبيق (تبقى ويب)
  • إرسال واتساب من التطبيق
  • تعديل أسعار الصرف من التطبيق

التطبيق 2 — تطبيق التوصيل (Flutter)

1) الحساب

  • دخول للسائق / المندوب فقط
  • الملف الشخصي للسائق

2) الطلبات

  • قائمة الطلبات المسندة (جديدة / قيد التوصيل / مكتملة)
  • تفاصيل: اسم الزبون، هاتف، عنوان، منتجات، مبلغ، طريقة الدفع
  • تحديث الحالة: استلام من المستودع / في الطريق / تم التسليم / تعذّر التسليم

3) الخرائط والتحصيل والإشعارات

  • فتح العنوان على Google Maps / Apple Maps
  • تتبع GPS حي (اختياري مرحلة لاحقة)
  • تسجيل تحصيل الكاش عند التسليم
  • إشعار عند إسناد طلب جديد
تطبيق التوصيل يحتاج غالباً API جديد من الـ Backend (سائقين + إسناد طلبات). قبل التسعير النهائي يُفضّل توضيح: إسناد يدوي أم تلقائي؟ مناطق/عمولات؟ هل مطلوب GPS حي؟

ما هو موجود حالياً (للمبرمج)

API جاهز تقريباً للزبون: Auth، Products، Categories، Brands، Cart، Orders، Addresses، External platforms + preview، Purchase requests + payment، Currency.

موجود أيضاً: لوحة أدمن ويب + تطبيق Android بسيط (WebView) ليس بديلاً عن Flutter الكامل.

قد يحتاج Backend إضافي: API تطبيق التوصيل + تحسينات موبايل (رفع صور، pagination، push tokens).

طلب التسعير من المبرمج

  1. تكلفة تطبيق الزبون (Android + iOS)
  2. تكلفة تطبيق التوصيل (Android + iOS) — منفصل
  3. تكلفة الاثنين معاً (إن وُجد خصم)
  4. مدة التنفيذ التقريبية لكل تطبيق (بالأسابيع)
  5. هل السعر يشمل: تصميم UI/UX؟ ربط API؟ تطوير Backend؟ النشر على المتاجر؟ صيانة بعد التسليم؟
  6. تقسيم المراحل المقترح (MVP ثم تحسينات)
  7. طريقة الدفع المقترحة (عربون / مراحل)

مقترح المراحل

  • A — MVP زبون: تسجيل + متجر + منتج + سلة + دفع + طلباتي + لصق رابط خارجي
  • B — تحسينات زبون: تصفح المنصات + Wishlist + Push + تحسينات UI
  • C — تطبيق التوصيل: سائق + طلبات مسندة + تحديث حالة + خرائط
  • D — اختياري: GPS حي + إشعارات موقع للزبون
