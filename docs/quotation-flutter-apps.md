# عرض متطلبات — تطبيقات وصلة (Wasla)

**الغرض:** هذا الملف لإرسال عرض متطلبات لمبرمج/شركة تطوير لتقدير التكلفة والمدة.  
**المنصة المطلوبة:** Flutter (Android + iOS)  
**الخلفية الحالية:** نظام ويب جاهز (Laravel + API) — التطبيقات تتصل بنفس الـ Backend قدر الإمكان.

---

## ملخص المشروع

| # | التطبيق | الجمهور | الهدف |
|---|---------|---------|--------|
| 1 | **تطبيق الزبون** | العملاء | تسوق من متجر وصلة + طلب من مواقع خارجية + دفع ومتابعة الطلبات |
| 2 | **تطبيق التوصيل** | السائق / المندوب | استلام الطلبات، تحديث الحالة، تتبع التوصيل |

> يُرجى تسعير كل تطبيق **منفصل**، مع خيار خصم عند تنفيذ الاثنين معاً.

# التطبيق 1 — تطبيق الزبون (Flutter)

## 1) الهوية واللغة
- واجهة عربية بالكامل (RTL)
- هوية بصرية حسب براند وصلة (لون أساسي تقريباً `#1c7282`)
- دعم Android و iOS
- إشعارات Push (FCM)

## 2) الحساب والتسجيل
- تسجيل حساب جديد
- تسجيل دخول / تسجيل خروج
- عرض الملف الشخصي
- إدارة عناوين التوصيل (إضافة / تعديل / حذف)

## 3) المتجر المحلي (منتجات وصلة)
- تصفح المنتجات مع بحث وفلاتر (فئة، ماركة، بحث نصي)
- صفحة منتج:
  - صور متعددة
  - اختيار لون
  - عرض كل المقاسات؛ المقاس غير المتوفر يظهر معطّل (disabled)
  - السعر بالليرة السورية
  - إضافة للسلة مع الكمية
- قائمة الأمنيات (Wishlist) — اختيارية في المرحلة الأولى إذا أثّرت على السعر

## 4) الشراء من الخارج (ميزة أساسية)
المنصات المستهدفة: SHEIN، Trendyol، Temu، Noon، Amazon (وغيرها حسب إعدادات النظام).

مسارين:
1. **لصق رابط منتج** → معاينة السعر بالليرة (منتج + شحن + رسوم خدمة) → إضافة للسلة / إنشاء طلب شراء
2. **تصفح داخل المنصة** من داخل التطبيق (WebView أو كتالوج عبر API حسب ما هو متاح في الـ Backend)

## 5) السلة والدفع
- سلة مختلطة (منتجات محلية + منتجات خارجية إن أمكن)
- إتمام الطلب (Checkout)
- طرق الدفع المطلوبة:
  - كاش عند الاستلام
  - سيرياتيل كاش
  - MTN كاش
  - شام كاش
  - تحويل بنكي
  - رصيد المتجر (Store Credit)
- رفع صورة إيصال للدفعات التي تتطلب إثبات
- صفحة تأكيد الطلب

## 6) طلباتي ومتابعة الحالة
- قائمة طلبات المتجر المحلي
- قائمة طلبات الشراء من الخارج (Purchase Requests)
- تفاصيل كل طلب: منتجات، أسعار، حالة الطلب، حالة الدفع
- إشعارات عند تغيّر الحالة / تأكيد الدفع

## 7) التكامل التقني
- الاتصال بـ API الحالي (Laravel Sanctum)
- دعم الضيف للسلة ثم طلب تسجيل الدخول عند الدفع (مثل الموقع)
- رفع الصور (إيصالات الدفع)
- التعامل مع أسعار الصرف ورسوم وصلة كما في الـ Backend (بدون إعادة حساب محلي خاطئ)

## 8) خارج النطاق (ما لم يُطلب صراحة)
- لوحة تحكم الأدمن داخل التطبيق (تبقى ويب)
- إرسال واتساب من التطبيق
- تعديل أسعار الصرف من التطبيق

# التطبيق 2 — تطبيق التوصيل (Flutter)

## 1) الحساب والصلاحيات
- تسجيل دخول للسائق / المندوب فقط (حسابات مخصصة أو صلاحية role)
- الملف الشخصي للسائق

## 2) الطلبات
- قائمة الطلبات المسندة للسائق (جديدة / قيد التوصيل / مكتملة)
- تفاصيل الطلب:
  - اسم الزبون ورقم الهاتف
  - العنوان على الخريطة (إن توفر إحداثيات) + إمكانية الاتصال
  - المنتجات والكميات
  - المبلغ وطريقة الدفع (خصوصاً كاش عند الاستلام)
- تحديث حالة الطلب من التطبيق:
  - تم الاستلام من المستودع
  - في الطريق
  - تم التسليم
  - تعذّر التسليم (مع سبب)

## 3) الخرائط والتتبع
- فتح العنوان على Google Maps / Apple Maps
- (اختياري مرحلة 2) تتبع موقع السائق لحظياً للزبون/الأدمن

## 4) التحصيل
- تسجيل تحصيل الكاش عند التسليم
- ملاحظة إذا كان الدفع مسبقاً (تحويل / محفظة) فلا يوجد تحصيل

## 5) الإشعارات
- إشعار عند إسناد طلب جديد للسائق

## 6) التكامل التقني
- يحتاج غالباً **API جديد** من الـ Backend لأدوار السائقين وإسناد الطلبات  
  (حالياً النظام يدير الطلبات من لوحة الأدمن؛ تطبيق التوصيل يتطلب توسيع الـ Backend)

## 7) ملاحظة مهمة للمبرمج
قبل التسعير النهائي لتطبيق التوصيل، يُفضّل تحديد:
- هل الإسناد يدوي من الأدمن أم تلقائي؟
- هل يوجد مناطق توصيل / عمولات سائق؟
- هل مطلوب تتبع GPS حي؟

# ما هو موجود حالياً (للمبرمج)

الخلفية جاهزة جزئياً ويمكن البناء عليها:

**API جاهز تقريباً للزبون:**
- Auth (register / login / logout / profile)
- Products / Categories / Brands
- Cart / Orders / Addresses
- External platforms + preview رابط منتج
- Purchase requests + submit payment
- Currency

**موجود أيضاً:**
- تطبيق Android بسيط (WebView لـ SHEIN) — ليس بديلاً عن Flutter الكامل
- لوحة أدمن ويب: منتجات، طلبات، شراء من الخارج، مدفوعات، رصيد متجر، واتساب، إعدادات

**ما قد يحتاج تطوير Backend إضافي:**
- API كامل لتطبيق التوصيل (سائقين، إسناد، تحديث حالة من المندوب)
- تحسينات API للموبايل إن لزم (رفع صور، pagination، push tokens)

# طلب التسعير من المبرمج

يرجى إرسال عرض سعر يشمل:

1. **تكلفة تطبيق الزبون** (Android + iOS)
2. **تكلفة تطبيق التوصيل** (Android + iOS) — منفصل
3. **تكلفة الاثنين معاً** (إن وُجد خصم)
4. **مدة التنفيذ** التقريبية لكل تطبيق (بالأسابيع)
5. هل السعر يشمل:
   - تصميم UI/UX؟
   - ربط الـ API الحالي؟
   - أي تطوير Backend إضافي؟
   - نشر على Google Play و App Store؟
   - صيانة بعد التسليم (شهر / 3 أشهر)؟
6. تقسيم المراحل المقترح (MVP ثم تحسينات)
7. طريقة الدفع المقترحة (عربون / مراحل)
