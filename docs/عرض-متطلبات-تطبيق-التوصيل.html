عرض متطلبات — تطبيق التوصيل (وصلة)

نوع الملف: متطلبات لتقدير التكلفة والمدة فقط لهذا التطبيق
المنصة: Flutter (Android + iOS)
الجمهور: السائق / المندوب
ملاحظة: هذا التطبيق منفصل عن تطبيق الزبون
التاريخ: 2026-08-20

هدف التطبيق

تطبيق للسائق/المندوب لاستلام الطلبات المسندة، تحديث حالة التوصيل، التواصل مع الزبون، وتحصيل الكاش عند الحاجة.

خيارات التصميم (UI / UX) — مهم للتسعير

الخيار أ — تصميم UI/UX من الصفر (المطلوب تضمينه كخيار بالتسعير)
  • دراسة تدفق عمل المندوب (User flow)
  • تصميم شاشات كاملة من الصفر (Wireframes + UI نهائي)
  • هوية بصرية خاصة بتطبيق التوصيل (متناسقة مع وصلة لكن مخصّصة للسائق)
  • تصميم حالات الشاشات: فارغ، تحميل، خطأ، نجاح
  • تسليم ملفات التصميم قبل أو مع التطوير (Figma أو ما يعادله)
الخيار ب — بدون تصميم من الصفر: واجهة جاهزة/قوالب Flutter مع تخصيص ألوان وصلة فقط.
يُرجى تسعير الخيار أ والخيار ب منفصلين حتى نختار الأنسب.

المتطلبات الوظيفية

1) الحساب والصلاحيات

  • تسجيل دخول للسائق / المندوب فقط
  • الملف الشخصي للسائق
  • صلاحيات مختلفة عن الزبون والأدمن

2) الطلبات

  • قائمة الطلبات المسندة: جديدة / قيد التوصيل / مكتملة
  • تفاصيل الطلب:
    • اسم الزبون ورقم الهاتف + إمكانية الاتصال
    • العنوان (مع فتح الخريطة إن توفرت إحداثيات)
    • المنتجات والكميات
    • المبلغ وطريقة الدفع (خصوصاً كاش عند الاستلام)
  • تحديث حالة الطلب من التطبيق:
    • تم الاستلام من المستودع
    • في الطريق
    • تم التسليم
    • تعذّر التسليم (مع سبب)

3) الخرائط والتتبع

  • فتح العنوان على Google Maps / Apple Maps
  • اختياري مرحلة لاحقة: تتبع موقع السائق لحظياً (GPS حي) للأدمن/الزبون

4) التحصيل

  • تسجيل تحصيل الكاش عند التسليم
  • إذا الدفع مسبقاً (تحويل/محفظة) لا يوجد تحصيل

5) الإشعارات

  • إشعار Push عند إسناد طلب جديد للسائق

الجانب التقني (مهم)

حالياً الطلبات تُدار من لوحة الأدمن على الويب.
تطبيق التوصيل يحتاج غالباً تطوير Backend / API جديد: حسابات سائقين، إسناد طلبات، تحديث حالة من المندوب، تحصيل، إشعارات.

يرجى توضيح في العرض:

  • هل سعر التطبيق يشمل تطوير الـ API؟
  • أم التطبيق فقط على افتراض أن الـ API سيُوفَّر من طرفنا؟

أسئلة قبل التسعير النهائي

  • هل إسناد الطلبات يدوي من الأدمن أم تلقائي؟
  • هل يوجد مناطق توصيل / عمولات سائق؟
  • هل مطلوب تتبع GPS حي من المرحلة الأولى أم لاحقاً؟

مقترح المراحل

  • MVP: دخول سائق + طلبات مسندة + تحديث حالة + اتصال/خرائط + تحصيل كاش + إشعارات
  • مرحلة 2 (اختياري): GPS حي + لوحة متابعة أدق

طلب التسعير (تطبيق التوصيل فقط)

  1. السعر مع تصميم UI/UX من الصفر (الخيار أ) — Android + iOS
  2. السعر بدون تصميم من الصفر (الخيار ب — قوالب جاهزة) — Android + iOS
  3. مدة التنفيذ لكل خيار
  4. هل السعر يشمل تطوير Backend/API؟ إذا لا، كم تكلفة الـ API لوحدها؟
  5. هل يشمل النشر على المتاجر + صيانة بعد التسليم؟
  6. تقسيم الدفع (عربون / مراحل)
  7. تسعير GPS الحي كإضافة اختيارية منفصلة

خارج النطاق

  • تطبيق الزبون (ملف متطلبات منفصل)
  • لوحة أدمن كاملة داخل تطبيق التوصيل (يمكن شاشة بسيطة لاحقاً إن لزم)
