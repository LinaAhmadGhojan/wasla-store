عرض متطلبات — تطبيق التوصيل (وصلة)
التاريخ: 2026-08-20

هذا الملف لتطبيق التوصيل فقط (منفصل عن تطبيق الزبون).
المنصة: Flutter (Android + iOS)
الجمهور: السائق / المندوب

==================================================
هدف التطبيق
==================================================
استلام الطلبات المسندة، تحديث حالة التوصيل، التواصل مع الزبون، تحصيل الكاش عند الحاجة.

==================================================
خيارات التصميم UI/UX — مهم للتسعير
==================================================

الخيار أ — تصميم UI/UX من الصفر (مطلوب تضمينه كخيار)
- دراسة تدفق عمل المندوب (User flow)
- تصميم شاشات كاملة من الصفر (Wireframes + UI نهائي)
- هوية بصرية خاصة بتطبيق التوصيل (متناسقة مع وصلة)
- حالات الشاشات: فارغ / تحميل / خطأ / نجاح
- تسليم ملفات التصميم (Figma أو ما يعادله)

الخيار ب — بدون تصميم من الصفر
- قوالب Flutter جاهزة + تخصيص ألوان وصلة فقط

يرجى تسعير الخيار أ والخيار ب منفصلين.

==================================================
المتطلبات الوظيفية
==================================================

1) الحساب
- دخول سائق/مندوب فقط
- ملف شخصي
- صلاحيات مختلفة عن الزبون

2) الطلبات
- قائمة: جديدة / قيد التوصيل / مكتملة
- تفاصيل: اسم الزبون، هاتف + اتصال، عنوان + خريطة، منتجات، مبلغ، طريقة الدفع
- تحديث الحالة:
  • تم الاستلام من المستودع
  • في الطريق
  • تم التسليم
  • تعذّر التسليم (مع سبب)

3) الخرائط
- فتح العنوان على Google Maps / Apple Maps
- اختياري لاحقاً: GPS حي

4) التحصيل
- تسجيل تحصيل الكاش عند التسليم
- لا تحصيل إذا الدفع مسبقاً

5) الإشعارات
- Push عند إسناد طلب جديد

==================================================
الجانب التقني
==================================================
حالياً الطلبات من لوحة أدمن ويب.
تطبيق التوصيل يحتاج غالباً Backend/API جديد:
حسابات سائقين + إسناد + تحديث حالة + تحصيل + إشعارات

وضّح في العرض:
- هل السعر يشمل تطوير الـ API؟
- أم التطبيق فقط بافتراض أن الـ API سيُوفَّر من طرفنا؟

أسئلة قبل التسعير النهائي:
- إسناد يدوي من الأدمن أم تلقائي؟
- مناطق توصيل / عمولات سائق؟
- GPS حي من البداية أم لاحقاً؟

==================================================
المراحل
==================================================
MVP: دخول + طلبات + حالة + اتصال/خرائط + تحصيل + إشعارات
مرحلة 2: GPS حي + متابعة أدق

==================================================
طلب التسعير (التوصيل فقط)
==================================================
1. السعر مع تصميم UI/UX من الصفر (الخيار أ) — Android + iOS
2. السعر بدون تصميم من الصفر (الخيار ب)
3. مدة التنفيذ لكل خيار
4. هل يشمل Backend/API؟ إذا لا، كم تكلفة الـ API لوحدها؟
5. نشر المتاجر + صيانة؟
6. تقسيم الدفع
7. GPS الحي كإضافة اختيارية منفصلة

==================================================
خارج النطاق
==================================================
- تطبيق الزبون (ملف منفصل)
- لوحة أدمن كاملة داخل تطبيق التوصيل
